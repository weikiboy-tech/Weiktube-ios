# Feature-Parität Android → iOS

Stand: 25. November 2026. Referenz ist **Weiktube Android 1.3.23**, Commit `a7e0a9221e73d3d9c361f614adcb9e027fb70c35` im [Originalrepository](https://github.com/weikiboy-tech/Weiktube/tree/a7e0a9221e73d3d9c361f614adcb9e027fb70c35).

**Dies ist ein Implementierungs- und Evidenzinventar, keine abgeschlossene Portierungsabnahme.** Alle **163 Android-Funktions-IDs** aus der Quellcodeprüfung sind enthalten. Keine existierende Funktion wird wegen fehlender iOS-Umsetzung aus der Liste entfernt. Die letzten Zeilen ergänzen die iOS-spezifischen Anforderungen. Android-Pfade beziehen sich exakt auf den gepinnten Commit; iOS-Pfade auf dieses Repository. Android-Testdateien sind Quellenhinweise, keine hier erneut ausgeführten Tests.

## Statusregeln

| Status | Aussage |
| --- | --- |
| Noch nicht implementiert | Der konkrete Funktionspfad fehlt. Eine verwandte Ansicht oder gespeicherte Einstellung genügt nicht. |
| In Entwicklung | Ein Teil ist vorhanden, aber ein benannter technisch umsetzbarer Teil fehlt oder weicht wesentlich von der Referenz ab. |
| Implementiert | Konkreter Produktionscode liegt vor. Dieser Status besagt ausdrücklich **nicht**, dass das iOS-App-Target gebaut oder praktisch abgenommen wurde. |
| Automatisiert getestet | Der in dieser Zeile bezeichnete abgegrenzte Logik-/Fixturepfad wurde wirklich ausgeführt. Er überträgt sich nicht automatisch auf UIKit/WebKit oder die gesamte Funktion. |
| Im Simulator getestet | Der Simulator hat das konkret beschriebene Verhalten ausgeführt. Commit, Testablauf und geprüfte Systemversion stehen in [TESTING.md](../TESTING.md). |
| Auf echtem Gerät bestätigt | Erfordert dokumentierte Geräteabnahme. **Keine Zeile hat diesen Status.** |
| Plattformbedingt eingeschränkt | Eine konkrete öffentliche Plattform-/Dienstgrenze und die vorhandene Alternative sind benannt. Dies ist kein Sammelstatus für fehlenden Code. |

## Tatsächlich ausgeführte Evidenz

- **41 Swift-XCTest-Fälle bestanden, 0 Fehler**, mit Swift 6.4.3 auf Linux über `Package.swift`: 9 Router-, 9 Präsentationszustands-, 7 Inbox-, 3 AtomicJSONFile-, 5 PlaybackRestoration- und 8 ReleaseMetadata-Tests. Das Package kompiliert ausschließlich die sechs ausdrücklich in `Package.swift` aufgeführten Produktionsdateien.
- **70 MediaBridge-Verhaltensprüfungen bestanden**. Die echte JavaScript-Datei wird in einem VM-/DOM-Fixture ausgeführt, ohne YouTube-Netzwerk oder echte WKWebView.
- Filter-Runtime-Fixtures mit tatsächlichen gebündelten Scriptlets sowie `vendor-adblock.mjs --check` bestanden; Original-RSA-Signatur/Manipulation und Quellreproduzierbarkeit geprüft.
- Xcode 26.2 hat das Release-Archiv für iOS mit eingebetteter Share Extension gebaut. Der Build ist unsigniert. [Xcode-Protokoll](https://github.com/weikiboy-tech/Weiktube-ios/actions/runs/45607195125/job/139181072997) Die aktuellen Simulatorergebnisse stehen in [TESTING.md](../TESTING.md).

Details: [TESTING.md](../TESTING.md), [ADBLOCK-VALIDATION.md](ADBLOCK-VALIDATION.md), [KNOWN-LIMITATIONS.md](KNOWN-LIMITATIONS.md). Einzelne bereits vorhandene Tests erfassen häufig nur einen Teil der Zeile; diese Reichweite steht im Umsetzungstext.

## Abnahmeregel

Ein positiver Syntax-/Fixture-/Core-Test ersetzt keine Live-Wiedergabe oder Installationsabnahme. Die vollständige Portierung ist erst abgenommen, wenn alle als fehlend/in Entwicklung markierten fachlichen Punkte entschieden bzw. umgesetzt sind, der gesamte Xcode-Build besteht und die kritischen Wege aus `TESTING.md` mit konkretem Simulator-/Geräteprotokoll belegt sind. Neue Testergebnisse müssen mit Datum, Quelle/Commit, Umgebung und tatsächlicher Reichweite eingetragen werden.
